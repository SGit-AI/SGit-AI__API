The reading, in one sentence: **the protocol and its read contract are already product-grade (a static file host can serve them), the storage and CLI are product, and everything that makes the vault *deployable by a stranger* — the UI's build, the auth coupling, the deploy artefacts, Terraform, the docs — is custom-built or genesis.** That is exactly the shape of a Villager job, and it is why "same features, new shape" is the right framing rather than "add features".

## 4. The questions I could not answer from the code (need you or a human action)

1. **Read-only share tokens.** `sgit share` no longer exists in CLI 0.16; the vault web still opens RO tokens by downloading a *transfer*. Is the RO-token feature part of "same vault features", or is it a Send feature the vault web happens to expose? If parity, the new API needs the two transfer routes it uses (`download`, `info`) as a **vault-scoped snapshot endpoint** — which is a small new route (Explorer) or a temporary proxy to Send (transitional).
2. **Public previews** (`/api/public-preview/*`, `sg-link-card`): same question. They are crawler/OG rendering of a deliberately public vault preview, transfer-backed.
3. **Which AWS account and region** for the new footprint, and who runs the OIDC bootstrap (`deploy/aws/github-oidc-role.cfn.yml` exists; `AWS_DEPLOY_ROLE_ARN` has never been set anywhere).
4. **Registry** for the image: GHCR under `SGit-AI` (recommended: no extra secrets, org-scoped) or Docker Hub `diniscruz/*`.
5. **DNS**: `vaults.sgit.ai`, `dev.vaults.sgit.ai`, and while we are there `deploy.sgit.ai` (still not resolving) — human action at the DNS provider.
6. **The CLI team**: default base URL change, dropping the `/api/auth/whoami` probe, and static-clone status (the CLI README documents `--transport auto`; PyPI 0.16.0 does not have it).
7. **sgit.ai handover**: `sgit.ai/deploy/vault.json` still reads vault `fyofmkvr` from `dev.send.sgraph.ai`; the deploy docs vault `ivpijuvg` has never been pushed to a live server. This pack makes vaults.sgit.ai that server.
8. **Terraform scope**: AWS only in this pack (mirror the three CFN shapes), or also GCP? Recommend AWS only; Cloud Run stays a documented `gcloud` command until a second consumer needs a module.
