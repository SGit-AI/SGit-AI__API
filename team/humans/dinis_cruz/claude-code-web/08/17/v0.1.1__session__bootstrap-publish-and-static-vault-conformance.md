## Part 2 — The static-vault brief, turned into working artifacts

Everything the brief's build order asks for that can exist today, exists on this branch:
the reference vault, the projection deploy, and the conformance check in CI. Findings
below are code-verified against sgit-ai v0.15.0 (PyPI).

### What was proven (hermetically, no external services)

1. **`sgit init` + `commit` work fully offline.**
2. **The named branch is NOT forwarded by commit** — in a never-pushed vault the named
   ref (what a read key opens) points at the empty init commit. `sgit push` is what
   forwards clone → named. **A static publish of a never-pushed vault serves an empty
   vault** — subtle and worth a docs note in the CLI.
3. **The origin server runs locally in-memory**: `pip install sgraph-ai-app-send`
   (Python ≥3.12; needs `mcp<2` pinned — `fastapi-mcp` 0.4.0 breaks against `mcp` 2.0),
   `SEND__STORAGE_MODE=MEMORY`, uvicorn. `sgit push` against it succeeds, and the local
   `bare/` mirror is byte-parity with the server afterwards — so **the whole vault
   lifecycle (create → commit → push → publishable projection) runs hermetically**.
   This is also an accidental first rehearsal of the extraction: the PyPI-installed User
   service boots standalone with two environment tweaks.
4. **The static read claim holds at the storage layer**: every object in `bare/` is
   fetchable byte-identical from a plain static file server at the live API's path shape,
   and the first filename any reader needs derives from the read key alone
   (`Vault__Crypto.derive_ref_file_id`).
5. **The CLI cannot clone from a static host today**: `sgit clone` goes to
   `POST /api/vault/batch/<id>` and fails (its only fallbacks are Lambda-502 → presigned
   S3, and per-file *batch* retries). The browser transport's `SG_STATIC` fan-out has no
   CLI counterpart. Pinned by `test__cli_clone_stops_at_batch` as a good-failure test.

### CLI findings to file upstream (sgit CLI team)

| Finding | Detail |
|---|---|
| `sgit_rk1_…` shorthand not parsed | The read-key format printed on sgit.ai pages (`sgit_rk1_<hex>:<vault_id>`) is not recognised by `sgit clone` v0.15.0 — it derives wrong keys and reports "no branch index and no named ref". Raw `--read-key <hex> <vault_id>` works. Either the CLI should strip the prefix or the sites should print the raw form. |
| Static mode request | `sgit clone --static` (or auto-detect): fan `batch_read` out to parallel `GET /api/vault/read/…` — the exact split the brief describes and the browser already ships. This flips the repo's pinned conformance test into a full clone-from-Pages check. |
| Named-ref staleness | "Publish = push": document that a vault that was only init+committed serves an empty named branch to read-key readers. |
