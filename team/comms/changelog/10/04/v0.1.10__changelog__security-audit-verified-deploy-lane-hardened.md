# Changelog — security audit verified with the pinned deps; deploy lane hardened (4 Oct 2026)

## What changed

- **Merged** the AppSec session's branch: the vendored Cloudflare `security-audit` skill
  (`.claude/skills/security-audit/`, MIT, pinned `c1c8a8c`) and the two audit runs under
  `team/roles/appsec/reviews/10/04/v0.1.10__security-audit__sg-api/`.
- **Verified** the audit with the baseline dependencies installed (the audit was source-only):
  `VERIFICATION.md` in that folder. Six origin leads confirmed; the deploy-lane finding confirmed.
- **Deploy lane hardened** (this repo's code; nothing deployed yet, so no behaviour change for any user):
  - `deploy/aws/github-oidc-role.cfn.yml`: one role **per stage**, trust = that stage's
    Environment subject only; IAM writes only on `role/sgit-vaults-lambda--<stage>` and only with
    the new permissions boundary `sgit-vaults-lambda-boundary`; `PassRole` to Lambda only; explicit
    denies on editing any deploy role and on boundary/policy tampering; bucket grant is an explicit
    create/configure list with no object or policy actions.
  - `deploy/aws/lambda.cfn.yml`: the execution role carries the boundary.
  - `.github/workflows/deploy-aws-lambda.yml`: one Environment-bound job does ECR → CFN → smoke →
    parity → CloudFront check; every input and secret reaches shell through `env:`; `id-token: write`
    on that job only; an empty access token **fails** the deploy unless `open_instance=true`.
  - Callers: `secrets: inherit`; Environment secrets `AWS_DEPLOY_ROLE_ARN` and
    `SGIT_VAULTS__ACCESS_TOKEN` (same names in each Environment); `open_instance` dispatch input.
  - `tests/unit/deploy/test_deploy_templates.py` (+ `pyyaml` in `requirements-test.txt`): the IAM
    and workflow invariants as tests; `deploy/aws/README.md` rewritten to match.

## Test impact

**SHOULD break (good failure):**
- `tests/unit/deploy/test_deploy_templates.py` — if anyone widens an IAM resource back to
  `sgit-vaults-*`, drops a boundary condition, adds a wildcard OIDC subject, interpolates an
  input or secret into `run:`, or defaults a caller to an open instance.

**Should NOT break (bad failure):**
- The original unit tests, the vault-conformance suite, the parity gate (unchanged), and the deploy
  lane's `tests` and `build-image` jobs. The `deploy` job skips (notice) until the Environment
  secrets exist.

## Operator-visible changes

- The bootstrap is now three stacks (`sgit-vaults-github-oidc--{dev,main,prod}`), and the two
  secrets are **Environment** secrets with stage-independent names. The old repository-level
  `SGIT_VAULTS__ACCESS_TOKEN__{DEV,MAIN,PROD}` names are gone.
- Prod's required reviewers are asked once per deploy (one job holds credentials).
