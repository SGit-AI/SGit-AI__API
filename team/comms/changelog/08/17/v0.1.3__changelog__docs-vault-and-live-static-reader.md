## What changed

1. **The reference vault is now the SGit API docs vault.** New content:
   `vault/docs/{what-is-the-sgit-api, read-contract, static-hosting, roadmap}.md`;
   `content.json` gains a `docs` nav; the vault app (`vault/index.html`) is now a docs
   site — sidebar navigation plus a minimal inline markdown renderer, reading pages over
   the `sg.vfs` bridge. New vault commit `obj-cas-imm-a67bdfcd6904`, named branch
   forwarded via a local in-memory SG/Send server (same hermetic flow as before).
2. **`pages/` — the static site source for GitHub Pages**, replacing the workflow's inline
   heredoc landing page:
   - `pages/reader.js` — a ~90-line read-only vault reader (WebCrypto / Node ≥ 19)
     mirroring `Vault__Crypto`: HMAC ref-id derivation, AES-GCM `iv‖ct`, metadata
     decryption, tree walk. Verified in Node against the committed store, both from
     disk and over HTTP against a stdlib static server.
   - `pages/index.html` — the publishing page per the sgit.ai method (describe →
     credential in the open → live → demonstrate → audit honestly → derived facts),
     with the docs vault decrypted and rendered **live in the page** from this same
     static origin — the sgit.ai/deploy mechanism, same-origin so no CORS surface.
   - `pages/llms.txt` — agent index of the static site: the walk, the derivations, the
     read key, the known gap, and repo pointers for agents without a JS runtime.
3. **`deploy-vault-pages.yml`** — assembles `_site` from `pages/*` + the `bare/` tree.

## Which tests SHOULD break (good failures)

- None of the existing suite: `VAULT_ID`/`READ_KEY` are unchanged, the store paths are
  unchanged, and all conformance tests read the committed store dynamically. A failure
  in `vault_conformance` after this change is a bad failure, not an expected one.

## Which tests should NOT break

- The full suite (11 tests) — verified green locally after the vault re-publish.

## Not covered by tests (known)

- `pages/reader.js` and `pages/index.html` have no pytest coverage (verified manually in
  Node against disk and HTTP). If the reader is kept long-term, a small Node check in CI
  — or a pytest that shells out to `node` — is the obvious follow-up; it would also
  catch a vault re-key that forgets to update the published constants.

## API surface impact

None. Still no API code in this repo. The read contract used by the projection is
unchanged.
