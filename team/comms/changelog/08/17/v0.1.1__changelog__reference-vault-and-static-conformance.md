## What changed

1. **Reference vault added at `vault/`** — a small published SG/Send vault (README,
   `content.json`, self-contained `index.html` app, `app.json`), with its encrypted
   object store `vault/.sg_vault/bare/` committed to git (side-by-side pattern).
   Vault ID `ivpijuvg`; read key published deliberately; write key escrowed out-of-band,
   `.sg_vault/local/` git-ignored.
2. **Static-vault conformance suite** at `tests/unit/vault_conformance/` (5 tests) —
   serves the committed `bare/` tree from a real static file server at the live API's
   path shape and verifies the read path, the leak boundary, the intended write/auth
   breaks, and the one real gap (CLI batch dependency).
3. **GitHub Pages deploy workflow** `.github/workflows/deploy-vault-pages.yml` — projects
   `bare/` to `https://<org>.github.io/<repo>/api/vault/read/ivpijuvg/bare/…` on pushes
   to `dev` that touch `vault/**`.
4. **`requirements-test.txt`** — adds `sgit-ai` (the conformance suite drives the real CLI
   and the real `Vault__Crypto` derivation).
5. **`.gitignore` / `.gitattributes`** — the vault boundary: `local/` + `work/` ignored;
   `.sg_vault/**` marked binary, no diff/merge.

## Which tests SHOULD break (good failures)

| Test | Breaks when | Why that is good |
|---|---|---|
| `test__cli_clone_stops_at_batch` | the sgit CLI ships static fan-out (batch → parallel GETs) | Conformance gained — replace with an assertion that the clone **succeeds** and matches `vault/`'s working tree |
| `test__every_committed_object_is_served_byte_identical` | someone edits `vault/.sg_vault/bare/` by hand, or commits a re-export partially | Ciphertext drift must be loud; the store is regenerated by `sgit`, never hand-edited |
| `test__named_ref_is_derived_from_the_read_key_alone` | the vault is re-keyed/re-created without updating `VAULT_ID`/`READ_KEY` constants (tests + workflow) | Rotation must be a deliberate, visible act — a published read key cannot be withdrawn |

## Which tests should NOT break (bad failures)

- `test__credential_tier_is_not_in_the_git_index` — if this fails, a write credential is
  in the git index: **treat as a security incident** (CLAUDE.md rule 9), rotate the vault
  key, scrub history.
- `test__write_attempt_is_refused` — a static host that accepts writes is not a static
  host; the test environment is broken.
- The original 6 unit tests — untouched by this change.

## API surface impact

None. No API code exists in this repo yet (see reality doc). The vault projection uses the
**read contract** of the live API (`GET /api/vault/read/<vaultId>/<filePath>`) as its path
shape — that contract is exactly what must not change during the extraction.

## Known tensions / notes for reviewers

- **CLAUDE.md rule 9 ("never commit vault keys") vs the published read key.** The brief is
  explicit that committing the read key of a deliberately published vault is correct and
  permanent, and the write key never enters the repo. Proposed CLAUDE.md amendment:
  distinguish *write* credentials (never) from *read keys of deliberately published
  vaults* (allowed, labelled, permanent). Pending Dinis's sign-off.
- The vault exists only in git + (once deployed) GitHub Pages. It has **not** been pushed
  to the live `dev.send.sgraph.ai` (no write token in the session) — so the official web
  UI cannot open it yet; the static projection and the committed store are the sources.
- GitHub Pages needs one-time enablement (Settings → Pages → Source: GitHub Actions) if
  `configure-pages` cannot self-enable.
