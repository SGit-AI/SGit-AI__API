Deploy sgit's server side

Technical, architectural and devops guidance for running your own zero-knowledge vault server — Docker, AWS, GCP, Heroku, or no server at all — plus the live status of the SGit API refactoring. These pages practice what they preach: everything below is being read out of an encrypted vault served by this static host. Your browser derived the filenames from a published read-only key, fetched ciphertext with plain GETs from this same origin, and decrypted it locally with the Web Crypto API. The host cannot read what you are reading.

The credential, in the open

  
The read key is published deliberately. It grants read, and only read — derived
  one-way from the vault key, it cannot be turned back into write access. The write key is
  escrowed out-of-band and has never entered the repository.

How this site works

  

    
ClaimMechanism, visible on this page

    
Names are computed, never listedThe first request was bare/refs/<hmac-of-read-key> — open the vault panel: no listing call appears

    
Reads are plain GETsThe ciphertext paths are the live API's read paths, served here by GitHub Pages; the repo's CI serves the same tree from a stdlib file server and asserts byte-identity on every push

    
The host cannot read the docsThis origin stores only obj-cas-imm-* ciphertext; decryption happens in this tab. Updating the docs is sgit push + re-projection — no page edits

    
Writes and auth break, by designA published vault is a read-only snapshot; the read key is the whole credential and the ciphertext is the protection

    
The one real gap is pinnedToday's sgit clone still needs the batch endpoint — a good-failure test in CI flips when the CLI ships static fan-out

  


  
Provenance, honestly

  
The deployment guides here were republished on 18 Aug 2026 from the
  SG/Send team's original deploy vault (fyofmkvr, commit
  obj-cas-imm-000f0325258c, the one behind
  sgit.ai/deploy) into this repository's
  vault, where they are now maintained alongside the code that will deploy — see the
  maintenance page in the viewer. Until the handover completes, the SG/Send team's vault
  remains the live source for sgit.ai/deploy. Before publication the tree and git index
  were scanned: the credential tier is git-ignored and leak-guarded by a unit test; no
  tokens or private keys appear in tracked files; the only credential here is the read key
  above, published on purpose. Everything in the repository — apart from the vault key —
  is public and open source (Apache-2.0).
